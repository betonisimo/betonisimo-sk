# URL страниц Vzory и Doplnky

Реализовано локально 29.10.2026. Раздел Služby не изменён. Существующие записи
не переименовываются массово, рабочая база и переменные окружения не изменялись.

## Использование

В форме создания/редактирования Vzor или Doplnok, в разделе
**Vyhľadávanie a zdieľanie**, поле **URL adresa** автоматически заполняется из
названия и показывает полный предпросмотр. Поле доступно только для чтения:
ручного ввода и кнопки **Použiť názov** больше нет.

Для существующего Q1 Drevo:

1. Открыть Vzor в админке.
2. Убедиться, что название — `Dizajnové betónové ploty Q1 Drevo`.
3. Поле URL само покажет `dizajnove-betonove-ploty-q1-drevo`.
4. Нажать **Uložiť zmeny**.

Новый адрес: `/katalog/dizajnove-betonove-ploty-q1-drevo`.
Прежний `/katalog/q1-drevo` будет возвращать постоянный HTTP 308 на новый.
ID записи, описание, фотографии, технические данные и SEO-поля сохраняются.

При создании и редактировании URL сразу следует за названием. При сохранении
сервер заново вычисляет адрес по названию и игнорирует отправленный `slug`, даже
если поле подменили через инструменты браузера. Словацкие диакритические знаки
убираются, слова разделяются дефисами.

Если адрес занят либо использовался раньше, автоматически подбирается свободный
вариант с номером `-2`, `-3` и т. д. В форме до сохранения показан предполагаемый
адрес; фактический суффикс определяется при сохранении и виден при повторном
открытии записи. Назначенный номер сохраняется при следующих сохранениях того
же названия. Длина адреса, включая суффикс, ограничена 160 символами.

Существующие записи с короткими/ручными URL переходят на адрес из полного
названия при следующем сохранении формы, с перенаправлением со старой ссылки.

## Хранение и перенаправления

Миграция Prisma не требуется: используется существующий `slug` в Collection/
Accessory и таблица StrankaObsah. Записи с ключами
`catalog-url-{collection|accessory}-{slug}` содержат `obsah.itemId`.

Текущий и прежние URL закрепляются за ID в одной Serializable-транзакции с
записью и SEO-настройками. Конфликты транзакций ограниченно повторяются.
Занятые адреса, в том числе исторические, пропускаются при подборе номера.
Произвольный URL с клиента не используется; адрес всегда строится из названия.

История хранит ID, поэтому после нескольких переименований все прежние адреса
ведут сразу на текущий URL. Проверка выполняется и при генерации метаданных, и
при чтении страницы. Ссылки каталога, canonical, og:url, Product URL аксессуара
и sitemap используют текущий `slug`. Кэш страниц раздела сбрасывается при
сохранении/удалении.

Исторические адреса не используются повторно, даже тем же объектом: постоянный
редирект может остаться в кэше браузера. После удаления записи адреса,
закреплённые новой системой, дают 404 и остаются зарезервированными, чтобы не
передавать старые ссылки другому объекту. Эти записи StrankaObsah нужно включать
в обычный бэкап базы.

## Проверки

- `npm test`: нормализация, автоматическое обновление URL при смене названия,
  нумерация занятых/исторических адресов, стабильность номера и лимит длины,
  история нескольких переименований и удаление, повтор конфликтов транзакций.
- ESLint изменённых файлов.
- `tests/e2e/catalog-urls.spec.mjs`: реальные формы создания/редактирования
  обоих типов, запись и повторное чтение БД, прямые 308 для браузера и Googlebot,
  canonical/og:url/sitemap/ссылки, автоматическая нумерация, неизменность
  SEO-данных, readonly-поле и подмена поля в браузере, удаление и параллельное
  создание двух одноимённых записей с разными URL.
  Проверена ширина формы 320, 390 и 1280 px.

E2E жёстко ограничены отдельной локальной базой:
`postgresql://catalog_url_test@127.0.0.1:55440/catalog_urls_test`.
По умолчанию сервер — `http://localhost:3110`, переопределение через
`CATALOG_URL_TEST_BASE_URL`. Данные для входа в этом изолированном окружении:
`editor-local-test` / `editor-local-test-only`. Эти значения не предназначены
для рабочего сайта. Тесты не отправляют письма и не загружают файлы в Blob.

Команда: `npx playwright test tests/e2e/catalog-urls.spec.mjs`.
Схема тестовой базы создаётся отдельно из prisma/schema.prisma; рабочая база
для тестов не используется. Сборка также выполняется с этой тестовой базой.

Проверки выполняются с отдельной копией исходников без `.env`, чтобы не
останавливать пользовательский dev-сервер и не перезаписывать его `.next`.
Production-сборка проверяется через `npx next build`: Prisma-схема не менялась,
повторная генерация клиента не нужна и могла бы конфликтовать с запущенным
пользовательским сервером на Windows.

Итог проверки автоматического режима: 39 модульных тестов, 4 браузерных
сценария, ESLint и production-сборка `npx next build` прошли. Readonly-поле
проверено по снимку экрана. Рабочий dev-сервер на порту 3000 не останавливался;
отдельный тестовый сервер и PostgreSQL после проверок остановлены.
